## 策略与盈利证据

CEX 是现货多头/现金：EMA200 与 42 根收益辨别趋势，压力/震荡不入场；收缩突破或回调恢复产生信号；本地校准逻辑回归再筛选，ATR 风险预算与跟踪退出管理仓位。DEX 是 12 项启发式评分、短期动量/ATR 筛选、双向报价成本检查和有限持有期。CEX 与 DEX 各自默认 $100，不能加总为一份 $100 的收益。

现有正面设计包括按时间训练/校准/留出、purge 标签重叠、token 分组、缺失标签不编造、费用和不成交处理、持久化未知回执、无实盘接口。但这些不等于证明盈利：

- CEX 标签是未来 6 根收盘价超过双边费用加 0.3%，与实际止损、跟踪、部分成交和持仓时间不一致；分类优势不是策略净期望。
- Brier/AP 优势只是一道研究门槛；反复使用留出集决定模型是否上线会产生选择偏差，相关币种/重叠样本也降低有效样本量。
- 扫描的 x2/x10/x100 是收盘价里程碑，不是可兑现收益；停盘、消失池、失败币缺失仍有删失与幸存者偏差。CSV 时点与标签语义需要供应商证据，格式验证不能证明真实性。
- 仓库没有实际前向成交账本、完整训练数据或已验证盈利的模型。原公网报告只记录 366 根 BTC 历史、318 条候选训练行，低于 CEX 600 行门槛；也明确没有确认同步的新鲜 WebSocket 订单簿。这是前作者的接入记录，本次未重做这些公网市场实验。

没有充分证据选出“更佳盈利策略”，因此没有把指标组合、网格、套利或加杠杆包装成更优收益。本次优先修改确定有问题的入场和成本约束。后续比较须冻结规则/阈值，使用独立数据目录、同一观察区间，对照现金与规则版本，记录成交后的净值、最大回撤、费用、拒绝/部分成交、暴露时间、陈旧估值和不可卖库存，并扣除订阅/运行费用。每次调参后使用新的前向观察期，不能反复优化同一个留出期。

## 已修复的确认问题

| 问题 | 影响 | 修复 |
|---|---|---|
| HTTP/适配器自动重定向 | 认证头可能转发、绕过目的地 HTTPS 检查与逐次预算 | 禁止重定向，填写最终可信 URL；签名费率请求限制官方 origin |
| 安全总分可抵消集中度失败，三布尔字段即放行 | 高风险/证据不完整候选仍可能入场 | 独立 market/risk 门槛；已知集中度失败阻断，缺失为未知；保留评分为观察排序 |
| 查询先过滤高分再取历史扫描 | 最新低分/不安全记录被跳过，旧高分仍可交易 | 每 token 先取最新记录，跨池、相同时间用 id 排序，再检查条件 |
| 缺口历史仍作为新鲜动量 | 不连续价格被用于 DEX 入场 | 连续性与实际 history_asof 检查，并在报价后复核过期 |
| 部分卖出未缩减 last_value | 断线估值与下一仓预算可能高估 | 按剩余库存比例缩减估值，预算读取成交后的账户 |
| 止损 IOC 部分成交后没有持久退出意图 | 价格反弹后尾仓可能不再退出 | 持久 exit_reason，继续按节流重试 |
| 仓位成本低估 | 实际费率/滑点使风险和仓位上限超预算 | 买卖实际费率加双边限价滑点预算，用买入最坏限价含费计算数量 |
| DEX 成本屏幕未计输出压力，原始单位经 float | 超过成本阈值或超过 2^53 后虚构整数库存 | 压力后的买入数量做反查，卖出同样折扣；Decimal 原始单位运算 |
| 旧行情反复训练获得新创建时间 | 过期数据模型继续被放行 | 同时验证 created_at 与 label_max_time，绑定网络/目标/费用/周期等模型上下文 |
| 增强特征用全样本覆盖率决定是否入模 | 留出特征分布参与模型选择 | 仅按训练段覆盖率选择增强特征，记录 purge 边界，两类均需至少 5 个样本 |
| 畸形费率/NaN 配置/非法 OHLCV | 零费率假象或异常数据进入计算 | 显式验证，拒绝非有限数、错误风险范围和非法 K 线 |
| 自动删除 35 天前净值 | 长期表现证据截断 | 保留净值路径，报告增加成交数、无成交状态、采样最大回撤、估值年龄与陈旧库存 |
| 禁用启动下载后维护任务仍立即下载 | 启动时出现非预期 API 消耗 | 小时维护先等待首个周期，尊重 bootstrap_on_start 的启动语义 |

例：$100 净值、0.5% 风险、5% 止损、双边每边 0.1% 费用、35bps 限价滑点，新的成本预算分母为 `0.05+0.001+0.001+2×0.0035=0.059`，名义预算约 $8.47，再用含费最坏买价算数量。高波动时低于交易所最小金额而不成交是预期行为；没有为了产生交易放宽风险。

## 模拟成交仍有的边界

CEX 的深度顺序、延迟、IOC、部分成交、过期拒绝与本地事务恢复是可测试的软件行为；可见深度折扣、延迟和未知回执概率没有真实订单标定。最佳 bid 估值不是全仓可执行清算价，盘口断线仍保留最后估值并标注 stale，真实损失可能继续扩大。抽样净值的最大回撤会漏掉两次估值之间的低点。小额尾仓可能因最小名义金额无法退出。

DEX 有报价不证明可卖、成功上链或能避开 MEV；失败/丢弃概率与 gas 都是设定情景，USDC 按 $1 估值。V1 Jupiter 已停止积极维护，未盲目改成 V2，也没有签名/广播接口。未知供应商的安全 JSON 仍是信任边界，程序验证身份、时点与字段，不能验证供应商没有撒谎。

HTTP 日计数不是 Binance 权重、Jupiter credits 或 RPC CU，多进程共享日预算，但主机间隔不是跨进程全局限速。预算耗尽也会阻止 HTTP 退出报价。降低扫描频率减少覆盖率，不能同时声称更省与全链完整。
