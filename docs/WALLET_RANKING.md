# 钱包扫描与排名设计

钱包扫描替代默认的百倍币目标扫描；CEX paper 仍独立运行。排名结果供跟单 bot 挑选领投（见 [COPY_TRADING.md](COPY_TRADING.md)），默认关闭，开启后也仍是 paper 模拟，不启用实盘、不使用 LLM。

## 比较口径

使用同一网络、同一币种计价（USD）、同一观察窗口。默认考察 90 天，辅以 30 天和 7 天结果。已实现盈亏应为卖出净收入减去已售出份额的历史成本，扣除归属该次买卖的费用。转入资金不是利润；转入代币、空投与未知成本不能按零成本计入交易能力。所有协议、失败币和未平仓库存都必须说明覆盖范围。

成交笔数分开显示交易所/链上成交次数与完整平仓次数。同一仓位分 100 次卖出不能制造 100 个独立胜利；排名样本以从开仓到清仓的持仓周期为单位，同时按代币聚合检查集中度。周期跨越窗口时必须带入有来源的成本，不得只截取窗口内卖出记录。

## 排名指标

| 维度 | 指标 | 作用 |
|---|---|---|
| 盈利能力 | 已实现净盈亏、已售成本收益率 | 金额展示；收益率用于比较，避免大本金天然领先 |
| 资源配置 | 净收益 / 已售成本、平均盈利 / 平均亏损、Profit Factor | 接受低胜率但盈亏比和配置合理的钱包 |
| 样本可信度 | 完整平仓数、独立代币数、活跃天数 | 对小样本降权，不奖励拆单刷成交数 |
| 单币依赖 | 最大盈利币贡献率、去掉该币后的净盈亏与收益率 | 识别一次百倍币主导的表现 |
| 持续性 | 7/30/90 天结果、盈利活跃周占比 | 区分短期幸运与跨阶段表现 |
| 未实现风险 | 未平仓亏损、剩余成本、未知估值 | 防止只卖赢家、把亏损永远留在账上 |

胜率必须展示，但不设高胜率硬门槛，也不直接与盈亏金额相乘。举例：10 次交易赢 3 次，每次净赚 400，输 7 次每次净亏 100，净赚 500，胜率 30%，Profit Factor 为 1200/700≈1.71。另一钱包胜率 90%，9 次各赚 10、1 次亏 200，净亏 110。前者在其它风险与样本相当时应排在后者前。

“去掉最大盈利币仍盈利”是稳健性证据，不是收益承诺。单币集中钱包应标为集中型/观察，不能仅凭高收益直接判定为高手，也不能断言其一定靠运气。钱包之间的关联地址、做市/套利、内幕分配和自成交不能仅靠排行榜识别。

## 已实现评分规则（待实证验证）

进入正式排序有三个硬性条件：90 天内至少 10 个完整持仓周期、3 个已完整平仓的代币；90 天已实现盈亏必须盖得住全部未平仓负盈亏；以及转出到其它地址的成本占比不超过 `max_censored_cost_fraction`（默认 25%）。不满足的钱包展示指标但标为观察，不给分数、不参与排名。

第三个条件是记录完整性而不是业绩：转出去的仓位最终卖了多少没人看得见，少量转出是正常操作，大比例转出意味着这个钱包的实际战绩根本不在链上这一段里。转出本身既不算胜也不算负，只累计缺口。

第二个条件不能省。分数里权重最大的 R 和 L 合计 0.70，都只统计已卖出的部分，只有 I 这一项（0.20）看得到浮亏。也就是说"卖掉赢家、把亏损锁在仓里"本身是净加分行为：实测中一个已实现 +12,000、未平仓 −15,000（真实净值 −3,000）的钱包，分数会高过一个真实净值 +1,500 的钱包两倍以上。这是最常见的假业绩形态，靠扣分压不住，必须直接拒绝。跨窗口周期不算完整样本，窗口内的卖出仍按历史成本计入已实现盈亏。金额均为扣费结果。

令 R 为已实现净盈亏 / 已售成本，L 为去掉最大净盈利币后的同口径收益率；I =（已实现净盈亏 + 所有未平仓负盈亏之和）/（已售成本 + 剩余成本）。I 是库存风险扣分代理，**不是**该窗口账户收益率或最大回撤。B =（完整周期总盈利 − 总亏损绝对额）/（总盈利 + 总亏损绝对额）。B 包含胜率、盈亏比及实际仓位配置的共同结果，避免重复奖励高胜率。

代码使用 f(x) = tanh(x / 0.2)，基础分 = 0.45 f(R) + 0.25 f(L) + 0.20 f(I) + 0.10 B。缺失分母不给正分。样本权重 = n/(n+20) × sqrt(min(代币数/8,1)) × sqrt(min(活跃周数/6,1))；这不是统计置信概率。正基础分再乘以（1 − 0.7 × 最大盈利币占所有正盈利币的贡献率），负分不会因集中度惩罚反而改善。最终乘以 100；所有分量都可在 JSON 中复核。

这些常数是透明的初始规则，未做真实历史优化或收益验证。只缩放本金和成交金额不改变分数；单币暴赚会被降权但并非一定排在所有稳健钱包之后。7/30 天指标用于对照，暂不混入 90 天总分。持有很多小额灰尘会影响“完整清仓”统计；代币数也不等于独立风险因子。需用事先冻结的权重、无幸存者偏差的历史钱包集和后续独立观察期验证后，才可讨论筛选效果。

## 来源拆分与记录缺口

库存按来源分成两部分：用计价资产买进来的（有成本基准）和转入进来的（成本未知）。卖出时按持有数量比例拆分收入——SPL 代币是同质的，无法确定卖掉的是哪一批，按数量拆是唯一中性的选择。

转入库存卖出的盈亏进 `external_origin_pnl_usd`，**不进 `cost_roi`、不算完整周期、不影响胜率**。空投砸中一个百倍币会在报告里显示出来，但不会被算成交易能力。未平仓估值同样按比例拆分：转入库存的浮盈不计入交易业绩，而且因为成本为零，它永远不会制造未平仓亏损。

转出的成本累计成 `censored_cost_usd`，除以总投入成本得到 `censored_cost_fraction`。转出时不实现盈亏、不产生胜负记录——但之前已经卖掉的部分，已实现盈亏照常保留。

一笔交易同时卖出多个代币时，收入按各代币的成本基准比例分摊，钱包被打上 `allocation_estimated`。这让每条腿得到相同的收益率，总额正确但分布是编的，而集中度指标恰好依赖分布，所以必须显式标注。

## 数据与成本

候选地址可从近期池成交记录发现，并支持用户地址名单。候选只表明近期活动，不代表该地址是最终交易受益人；聚合器、路由、机器人和托管地址需要进一步识别。发现本身存在池覆盖偏差。

完整排名需要可信的历史成本、卖出明细或可核验的持仓周期数据。供应商口径应明确采用 FIFO 或移动加权成本，不能混用会被未来买入改写的历史盈亏。Birdeye 官方区分 WAC 与 net_cash，并明确部分协议交易历史不回填；因此现成“胜率/PNL”字段也需要核对口径。[官方 PnL 说明](https://docs.birdeye.so/reference/get-wallet-v2-pnl)。

使用索引后的数据、6 小时缓存、小规模轮询与本地重排。仅修改权重时不重取历史；未完成分页的数据不进入正式榜单。大规模全链钱包发现与完整盈亏重建不能靠当前公共池接口免费完成。[Helius 钱包历史及关联代币账户说明](https://www.helius.dev/docs/enhanced-transactions/transaction-history)。

这套排名衡量历史表现是否值得进一步研究，不能直接证明跟单后盈利；延迟、价格冲击、仓位容量及钱包间资金转移会改变可复制结果。
